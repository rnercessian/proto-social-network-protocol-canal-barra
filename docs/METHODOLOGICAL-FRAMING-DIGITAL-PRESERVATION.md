# Methodological Framing: Digital Preservation and Lived Social Function

## Purpose

This document positions the Canal Barra repository within a broader methodological problem in digital preservation:

```text
Saving technical artifacts is not enough. A community archive must also preserve the lived social function of the system.
```

For Canal Barra, that means documenting not only IRC commands, access lists, website captures and datasets, but also how nicknames, operators, IRContros, status, trust, memory and offline relationships worked together.

## Core Position

Canal Barra should be documented as a hybrid social system:

```text
IRC real-time interaction
+ website persistence
+ nickname identity
+ access hierarchy
+ moderation practice
+ IRContros
+ photo captions
+ memory and reputation
```

The historical object is the loop, not any isolated component.

## Comparable International Preservation Problems

### 1. Early Virtual Worlds and Online Game Preservation

Projects that preserve early online worlds show that code alone is insufficient.

If a system was social, preserving only the software misses the behavior, norms, conflicts, rituals and community rules that made the system meaningful.

Canal Barra has the same problem:

```text
An access list proves hierarchy existed.
A rules page proves norms existed.
IRContro captions prove offline extension existed.
Oral history explains how those things were lived.
```

### 2. IRC Scholarship

Academic work on IRC helps frame Canal Barra as more than a chat room.

IRC channels had:

```text
channel identity
operators
status markers
public conversation
private messages
kicks and bans
local customs
network-specific culture
```

Canal Barra adds a Brazilian regional layer to that literature: a geographically named IRC channel with persistent web infrastructure, IRContros, photo archives, operator lists, rules, sponsorship, nightlife circulation and long-term memory.

### 3. BBS, FidoNet and Pre-Social-Media Archives

BBS and FidoNet preservation projects are useful comparisons because they also show that online communities existed before platform-era social media.

The key comparison is not technical equivalence.

The key comparison is social function:

```text
persistent identity
community norms
reputation
moderators / sysops / operators
message exchange
offline meetings
local or regional belonging
```

## What Canal Barra Adds

The repository's distinctive contribution is to translate a lived Brazilian IRC/web community into structured evidence:

```text
CSV datasets
JSON-LD / schema work
Wayback source registry
IRContro caption datasets
governance records
participation index scripts
oral-history questionnaire
```

This makes the archive readable both by humans and by future machines.

## Methodological Warning

Do not overstate external comparisons.

Avoid claims like:

```text
No one in the world has ever done this.
This is definitive.
This is scientifically proven by one external reference.
```

Prefer:

```text
This repository applies digital-preservation and social-history methods to an underdocumented Brazilian IRC/web community.
```

## Required Evidence Layers

A strong Canal Barra memory protocol needs at least five layers:

```text
1. Technical layer: IRC, ChanServ, access lists, topics, entry messages.
2. Web layer: CanalBarra.com pages, cadastro, photos, events, rules, voting, sponsors.
3. Social layer: nicknames, reputation, operators, voice, seniority, status.
4. Offline layer: IRContros, nightlife circulation, friendships, bands, relationships, jobs.
5. Interpretive layer: oral history, founder statements, participant testimony, verified/inferred distinction.
```

## Core Sentence

**Canal Barra should be preserved not as a dead website or a nostalgic chat room, but as a hybrid social system whose technical artifacts only become historically meaningful when connected to lived social practice.**
