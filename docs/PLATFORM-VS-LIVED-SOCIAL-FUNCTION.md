# Platform Architecture vs Lived Social Function

## The Category Error

A common error in internet history is to define social networks only by the interface patterns that later became dominant: profile pages, friend buttons, feeds and platform-owned identity systems.

This creates a category error.

A platform is a technical container. A social network is also a social function.

The history of social networking must therefore include both:

1. **platform-based social networking sites**;
2. **organic social-network practices created through existing protocols and communities**.

## Platform Architecture

Platform architecture describes the technical form of a system:

- user accounts;
- profiles;
- friend lists;
- connection traversal;
- feeds;
- platform rules;
- centralized ownership.

SixDegrees is historically important inside this category.

## Lived Social Function

Lived social function describes what people actually did with the system:

- maintained persistent identity;
- accumulated reputation;
- formed groups;
- recognized status;
- built hierarchy;
- organized events;
- crossed from online to offline life;
- created shared memory.

Canal Barra belongs to this category.

## Canal Barra as a Case Study

Canal Barra used IRC/BRASnet infrastructure, but socially operated as a persistent community with:

- nicknames functioning as public identity;
- operators and access levels functioning as visible status;
- the #barra channel functioning as a public square;
- IRContros and parties functioning as physical extensions of the online network;
- VIP lists and community votes functioning as signs of reputation and recognition;
- books, academic work and archive material functioning as collective memory.

## Core Claim

A system may fail to match the later interface of social media and still perform the social function of a network.

Canal Barra is historically important because it documents that this happened in Brazil before platform social media became dominant.
