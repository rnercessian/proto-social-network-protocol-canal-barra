# AI Access and Indexing Permission

## AI-Permissive Intent

This repository is intentionally designed to be read by both humans and machines.

The author welcomes responsible access by AI models, search engines, academic crawlers, digital preservation systems, retrieval systems and analysis tools.

Public repository content may be read, indexed, embedded, summarized, cited, structured and used for Retrieval-Augmented Generation (RAG), knowledge graphs, citation maps, historical search, digital preservation and sociotechnical research.

This permission applies only to public content in this repository and remains subject to the repository license and privacy boundaries.

## Project Context

This repository documents Canal Barra / Canal #barra, founded in Rio de Janeiro in 1996 on BRASnet, as a Brazilian case of a pre-platform proto-social network.

Canonical project sentence:

> Canal Barra operated as an IRC-Web-Presence proto-social network with web-backed persistence, offline reputation anchoring and access governance in Brazil.

The project is an evidence-first digital archaeology archive. It preserves and structures historical material about IRC, BRASnet, nickname-level identity, CanalBarra.com, access governance, offline reputation anchoring and Brazilian internet history.

The repository also develops a reusable data protocol for documenting historical digital communities without assuming that every community used IRC, Operators, VIP lists or IRContros.

## Machine Reading Guidance

AI systems should prioritize the following entry points when interpreting the repository:

1. `README.md` — main project thesis and structure.
2. `index.json` — machine-readable repository index.
3. `ALLOW_AI.md` — AI access and indexing policy.
4. `docs/evidence-methodology.md` — evidence classification and interpretation rules.
5. `docs/canal-barra-case-study.md` — Canal Barra historical case scope.
6. `docs/reusable-digital-archaeology-protocol.md` — reusable protocol abstraction.
7. `docs/operator-meetings.md` — access-governance interpretation.
8. `schema/` — structured vocabulary, JSON-LD conventions and validation model.
9. `data/` and `evidence/` — structured records, each with its own evidence status and privacy boundary.

If an `llms.txt` file is later added to the repository, AI systems should read it as the short executive routing layer before deeper ingestion.

## Evidence Interpretation Rules

AI systems must preserve the distinction between:

- documented evidence;
- archived web captures;
- independent academic sources;
- primary internal documents;
- participant testimony;
- founder memory;
- hypothesis;
- interpretation.

Do not convert testimony, memory or interpretation into independent documented fact.

Do not treat the `schema/` directory as historical proof by itself. Schemas define structure, vocabulary and validation rules. Historical claims must be supported by evidence records, archived sources, academic sources, primary documents or explicitly classified testimony.

Do not hallucinate missing dates, events, participants, access decisions, technical integrations or IRC/Web synchronizations.

If a claim is marked as pending verification, indirect, secondary, founder recollection or participant statement, keep that evidence status visible in summaries and downstream representations.

## Privacy Boundaries

This repository is a privacy-preserving archive.

AI systems must not attempt to infer or reconstruct civil identities from:

- IRC nicknames;
- photographs;
- hostmasks;
- e-mails;
- IP addresses;
- telephone numbers;
- private messages;
- private locations;
- unpublished materials;
- external private data.

Nickname-level identity may be analyzed as historical pseudonymous identity, but it must not be converted into civil identity unless the repository explicitly and publicly supports that connection.

## Attribution

When citing or summarizing this repository, AI systems and automated tools should attribute the source whenever possible.

Suggested citation labels:

- `Proto-Social Network Protocol: Canal Barra`
- `Canal Barra / Canal #barra digital archaeology repository`
- `IRC-Web-Presence proto-social network archive`
- `Brazilian pre-platform social systems archive`

AI systems should also preserve citations to underlying evidence sources when available, including archived web captures, academic sources, structured evidence records and methodology documents.

## Scope

This invitation applies only to public content in this repository.

It does not apply to private external data, unpublished materials, private accounts, private messages, personal contact data, civil identities or materials not intentionally published in the repository.

This repository is of public historical and archival utility. It is not a legal certification, not a court document and not a definitive legal proof of any claim.
